# 온라인 머더 미스터리 웹 보드게임 셀렉션 (ver.12.1.0)

브라우저에서 여는 정적 머더 미스터리입니다. 2~5명이 같은 방에 모여 역할을 고르고, 알리바이와 현장 증거를 조사한 뒤 진범을 지목합니다. 방 상태(인원, 카드, 단계, 투표, 타임라인)는 Firebase Firestore `rooms` 문서에 실시간으로 저장되고, 회원 가입 화면 없이 Firebase 익명 인증으로 들어갑니다. 게임은 디스코드에 접속하지 않고, 어느 음성방으로 이동할지만 안내합니다. 시나리오마다 진범은 미리 정해져 있으며 방을 만들 때 다시 뽑히지 않습니다.

플레이: [게임 바로가기](https://bit.ly/4i6nEcs)

## 주요 기능

### 방 만들기와 참가

시나리오를 고른 뒤 닉네임(최대 10자)을 넣고 **새 방 만들기** 또는 5자리 방 코드로 **참가**합니다. 방 코드는 생성 시 영문 대문자·숫자 5자리입니다. 한 방은 최대 5명이고, 로비(`LOBBY`)를 벗어나면 새 참가는 막힙니다. 이미 그 방에 있던 사람은 진행 중에도 같은 자리로 다시 들어옵니다.

### 역할과 인물

각 시나리오는 인물 5명입니다. 기본 인물 4명은 바로 고를 수 있고, `isDefault: false`인 5번째 인물은 5명이 모일 때만 열립니다. 고르지 않은 기본 인물은 NPC가 됩니다. 2인은 NPC 2명, 3인은 NPC 1명, 4·5인은 NPC가 없습니다. NPC가 그 시나리오의 진범일 수 있습니다. 방장은 **역할 무작위 배정**으로 열린 인물을 섞어 나눌 수 있습니다. 자기 화면의 **나의 비밀**에는 그 인물의 `secret`과 당일 `timeline`만 보입니다.

### 알리바이 카드

인물마다 알리바이 카드 5장이 방 전체의 공유 풀입니다. 누가 뽑든 그 카드는 풀에서 사라집니다. 자기 인물은 조사할 수 없습니다. 조사 횟수는 라운드마다 2인이 2장, 3인 이상이 1장입니다. 1~4라운드 토론 중에만 뽑을 수 있고, 밀담·5라운드 변론·최종 투표에서는 멈춥니다.

### 현장 증거

시나리오의 `clues`가 방의 공유 풀로 들어가고, 라운드당 1장을 무작위로 뽑습니다. 알리바이와 같이 1~4라운드 토론 중에만 수색할 수 있습니다. 뽑은 알리바이와 현장 증거는 **내 단서 보관함**에 남고, 이미지는 눌러 확대할 수 있습니다.

### 밀담

3인 이상만 2라운드와 4라운드 뒤에 5분 밀담(`R2_WHISPER`, `R4_WHISPER`)이 있습니다. 2인은 밀담 없이 다음 토론 또는 변론으로 갑니다. 방장이 체크박스로 **밀담룸 1**과 **밀담룸 2**에 사람을 넣습니다. 어느 쪽이든 4명 이상 체크된 상태에서 배정 버튼을 누르면 저장하지 않고, '밀담룸 한 곳에는 최대 3명까지 배정할 수 있어요.'라고 안내합니다. 배정 칸에는 현재 체크 인원이 `밀담룸 1 (2/3)`처럼 바로 표시됩니다. 3명 이하면 체크된 인원이 그대로 저장됩니다. 같은 사람을 양쪽에서 고르면 다른 쪽 체크가 풀리고, 배정할 때 반대편 방에서도 빠집니다. 배정된 사람에게는 디스코드 밀담방 이동 안내가 뜨고, 그 룸에 있는 사람끼리 **현장 증거**만 화면에 실물로 공개할 수 있습니다. 알리바이는 말로만 전합니다. 방장 화면에는 배정 버튼이 가려지지 않도록 이동 안내 팝업을 띄우지 않습니다.

### 사건 타임라인

프롤로그에서는 이야기와 `caseTimeline`(사건 기록)만 읽습니다. **사건 타임라인** 보드와 **내 타임라인 공개**는 1라운드부터 엔딩까지 열립니다. 보드는 시작 시각 순의 한 줄 목록이고, 같은 시각을 묶거나 모순을 표시하지 않습니다.

- **기록**은 시나리오의 공식 일지입니다. 시각과 장소는 대략적이라 기록만으로 거짓이 바로 드러나지는 않습니다.
- **진술**은 자기 타임라인에서 고른 줄입니다. 시민은 적힌 그대로만 올립니다. 엔딩 전에는 자기 진술을 내릴 수 있고, 엔딩 이후에는 올리거나 내릴 수 없습니다.
- 필터는 종류(전체·기록·진술)와, 진술이 올라온 인물입니다.
- 기록 줄의 **그 시각 진술 보기**는 그 기록의 시간 범위와 겹치는 진술만 보여 줍니다. 같은 버튼을 다시 누르거나 **전체 보기**로 돌아옵니다.
- 좁은 화면(폭 639px 이하)에서는 보드가 접힌 채로 시작합니다.

알리바이나 현장 증거를 타임라인에 고정하는 기능은 없습니다.

### 진범의 진실과 거짓

진범(`isKiller`이고 `fakeTimeline`이 있는 인물)만 줄을 공개할 때 진실과 준비된 거짓 중 하나를 고릅니다. 올린 뒤에는 다른 사람에게 같은 모양으로 보입니다. 진범 화면에는 그 선택이 가능하다는 안내가 나옵니다. 엔딩의 보드에서만 거짓 진술에 “거짓으로 밝혀짐”과 실제 줄이 붙습니다.

### 투표

5라운드 변론(10분)이 끝나면 2분 **최종 투표**입니다. 자기 인물은 고를 수 없고, 한 번 내면 바꿀 수 없습니다. 2·3인만 남은 NPC를 지목할 수 있습니다. 4·5인에는 NPC가 없습니다. 모두가 표를 내면 바로 엔딩으로 가고, 시간이 끝나면 그때까지 제출된 표만으로 집계합니다. 진범 플레이어가 낸 표는 집계에서 뺍니다. 최다 득표(동률 포함) 안에 진범이 있으면 시민 승, 없으면 진범 승입니다.

### 엔딩과 사건 정리

엔딩에는 승패 배지, 시나리오의 승리 제목, 사건의 진실(`endings.truth`), 인물별 에필로그가 나옵니다. **사건 정리**에는 다음이 있습니다.

- 인물별 공개 진술. 거짓으로 올린 줄은 거짓과 진실을 같이 보여 줍니다.
- 진범의 결정적 단서. 시나리오의 `decisiveClues`·`killerDecisiveClues`, 또는 진범 인물의 `decisiveClues`가 있으면 그 목록을 쓰고, 없으면 진범의 진실 타임라인·거짓 타임라인과 사건의 진실을 나란히 둡니다. 지금 들어 있는 다섯 시나리오는 별도 목록이 없습니다.
- 플레이어별 투표와 득표 요약.

### 재접속

방 코드와 플레이어 아이디는 브라우저 `localStorage`(`mmSession`)에 남습니다. 새로고침하거나 탭을 닫았다 열거나 화면이 다시 보이면, 그 방에 같은 자리가 남아 있을 때 그 배역으로 돌아옵니다. 조사한 카드, 밀담 배정, 타임라인 진술, 투표는 방 문서에 그대로 있습니다. 진행 중 재접속은 새 참가가 아니라서 인원 제한에 다시 세지 않습니다. 연결이 끊기면 **재접속 중…**이 뜨고, 스냅샷이 실패하면 잠시 뒤 같은 방을 다시 구독합니다. 탭이 보이는 동안 약 10초마다 `lastSeen`을 갱신합니다. 탭을 숨기면 그 갱신은 멈춥니다.

### 호스트 넘기기

타이머가 0이 되면 방장 화면이 다음 단계로 넘깁니다. 종료 시각은 방에 `timerEndsAt`으로 저장되어, 호스트가 바뀌어도 그 시각부터 이어서 줄어듭니다. 방장의 `lastSeen`이 약 30초 이상 끊기면, 입장 순서상 연결되어 있는 다음 사람(봇 제외)에게 호스트가 넘어갑니다. 방장은 **호스트 넘기기**로 직접 넘길 수도 있습니다. 넘길 다른 사람이 있고 엔딩이 아닐 때만 버튼이 보입니다. 호스트가 바뀌면 모두에게 짧은 안내가 8초간 뜹니다.

방장은 로비·프롤로그·최종 투표·엔딩이 아닌 단계에서 **다음 단계 요청**을 할 수 있습니다. 스킵 투표는 전원 찬성이어야 넘어가고, 반대가 한 표라도 있으면 취소됩니다. 방장은 요청과 함께 찬성으로 계산됩니다. 로비와 엔딩이 아닐 때 방장은 긴급 공지를 보낼 수 있고, 모두에게 한 번씩 팝업이 뜹니다.

### 단계 알림

단계가 바뀌면 새 단계 이름이 배너로 약 8초 뜹니다. 음소거가 아니면 짧은 진동이 나고, 페이지에서 포인터나 키 입력이 한 번 있은 뒤에는 소리도 납니다. 그 전에는 소리만 나지 않습니다. 상단 **알림**으로 소리와 진동을 끌 수 있으며, 그 설정은 `localStorage`에 남습니다. **BGM 토글**은 빗소리(웹 오디오로 만든 잡음)를 켜고 끄며, 단계 알림과는 따로 동작합니다. 헤더의 **룰북**에 인원·라운드·승리 조건이 적혀 있습니다.

## 게임 진행 방법

1. **시나리오 선택.** 다섯 사건 파일 중 하나를 고릅니다.
2. **로비.** 닉네임을 입력하고 방을 만들거나 코드로 참가합니다. 음성은 따로 연 디스코드 채널을 쓰는 것을 권합니다.
3. **용의자 선택 (`LOBBY`).** 인물을 고릅니다. 2명 이상이 모두 고르면 방장이 프롤로그로 넘깁니다. 방장이 역할을 무작위로 나눌 수도 있습니다.
4. **프롤로그 (`PROLOGUE`).** 이야기와 사건 기록을 읽습니다. 방장이 **사건 현장 조사 시작**으로 1라운드에 들어갑니다.
5. **1라운드 (`R1`, 15분).** 알리바이와 현장 증거를 조사하고 토론합니다. 타임라인 공개가 열립니다.
6. **2라운드 (`R2`, 15분).** 조사를 이어 갑니다.
7. **1차 밀담 (`R2_WHISPER`, 5분).** 3인 이상만 해당합니다. 방장이 밀담룸을 배정하고, 배정된 사람은 현장 증거를 화면에 공개할 수 있습니다. 2인은 이 단계를 건너뛰고 3라운드로 갑니다. 밀담 중에는 새 조사를 할 수 없습니다.
8. **3라운드 (`R3`, 15분).** 다시 모여 조사와 토론을 합니다.
9. **4라운드 (`R4`, 15분).** 마지막 조사·토론입니다.
10. **2차 밀담 (`R4_WHISPER`, 5분).** 3인 이상만 해당합니다. 2인은 건너뛰고 변론으로 갑니다.
11. **5라운드 변론 (`R5_DEFENSE`, 10분).** 알리바이 조사와 현장 증거 뽑기가 멈춥니다. 가진 단서로 결백을 말합니다.
12. **최종 투표 (`FINAL_VOTE`, 2분).** 진범을 한 명 지목합니다.
13. **엔딩 (`ENDING`).** 진실, 에필로그, 사건 정리를 보고 처음 화면으로 돌아갑니다.

토론·밀담·변론 중에는 방장이 스킵 투표를 걸 수 있습니다. 제한 시간이 끝나면 방장 클라이언트가 다음 단계로 넘기고, 투표 단계에서는 제출된 표로 엔딩을 엽니다.

## 테스트 모드

주소에 `?test=1`을 붙이거나, 헤더의 **테스트 모드**를 누릅니다. 버튼은 그 쿼리를 넣거나 빼고 페이지를 다시 엽니다. 켜져 있으면 버튼 문구는 **테스트 종료**가 됩니다. `js/main.js`는 이 쿼리가 있을 때만 `js/devmode.js`를 불러오고, 화면 한쪽에 **TEST DEV** 패널이 붙습니다. 이 상태에서 **만든** 방만 `test: true`가 됩니다. 봇 자동 조사·진술·단계 자동 실행은 그 플래그가 있는 방에서만 동작합니다.

패널 버튼은 다음과 같습니다. 호스트 판정은 화면을 다른 사람으로 바꿔 봐도, 테스트 모드를 연 본인 계정 기준입니다.

- **+ 봇 추가.** 방장만 사용할 수 있습니다. `BOT n`(`bot_n`, `isBot: true`)을 넣고, 로비에 빈 역할이 있으면 남는 인물을 봇에게 채웁니다. 봇을 포함해 5명을 넘기면 추가되지 않습니다.
- **다음 단계.** 방장이 스킵 투표 없이 단계를 넘깁니다. 로비에서는 2명 이상이 모두 역할을 골랐을 때만 프롤로그로 가고, 프롤로그에서는 1라운드로 갑니다. 최종 투표에서는 지금까지의 표로 엔딩을 엽니다.
- **봇 자동 조사.** 테스트 방의 1~4라운드 토론에서, 역할이 있는 봇이 알리바이를 뽑을 수 있는 만큼 뽑고 현장 증거를 한 장 뽑습니다.
- **봇 자동 진술.** 테스트 방에서 아직 올리지 않은 타임라인 줄을 봇이 공개합니다. 진범 봇은 줄마다 약 절반 확률로 준비된 거짓을 고릅니다.
- **타이머 x10.** 방장 화면의 남은 시간이 열 배로 빨리 줄어들도록 종료 시각을 다시 씁니다. 한 번 더 누르면 원래 속도입니다.
- **단계 넘길 때 자동 실행.** 체크하면 테스트 방에서 단계가 바뀔 때 봇 자동 조사와 봇 자동 진술을 이어서 실행합니다. 선택은 `localStorage`(`mmDevAutoOnPhase`)에 남습니다.
- **view as.** 이 브라우저에서만 다른 플레이어(봇 포함)의 화면으로 봅니다. 비밀과 보관함이 그 사람 기준으로 다시 그려집니다.

테스트 방의 방장 자리에서는 봇이 추가로 따라옵니다. 빈 역할은 로비에서 채워지고, 스킵 투표에는 찬성하며, 최종 투표에서는 규칙상 고를 수 있는 인물 중 하나를 무작위로 고릅니다. 같은 페이지의 `window.__mmTest`에는 방 삭제(`deleteRoom`), 방 존재 확인(`roomExists`), 강제 진행, 새로고침이 연결되어 있습니다. 패널 버튼은 아닙니다.

## 새 시나리오 추가 방법

`scenarios/scenario-<id>.js`에 `export default` 객체를 두고, `js/ui.js`의 `SCENARIOS` 배열에 그 `id`를 넣습니다. 선택 화면과 방 입장 모두 `../scenarios/scenario-<id>.js`를 동적 import 합니다. 이미지는 객체 안의 경로 문자열로 참조합니다. 방 생성 시 알리바이 풀은 인물마다 인덱스 `0~4`로 고정되므로, 인물당 알리바이 카드는 5장입니다.

코드가 읽는 형태는 아래와 같습니다.

```js
{
  id, title, subtitle, era, victim,
  killerId, // isKiller: true 인 인물의 id와 같게
  theme: {
    card: { borderClass, banner, bannerAlt, era, eraClass, title, titleClass,
            players, playersClass, blurb, buttonClass, buttonIconClass },
    lobby: { tag, tagClass, fallbackBanner, subtitle, titleFallback }
  },
  prologue: {
    bannerImg, location,
    story: ["문단", "..."] // 프롤로그에 그대로 나열
  },
  caseTimeline: [{ time, place, text }], // time 예: "22:00", "21:00~21:15"
  characters: [{
    id, name, role, isKiller, isDefault, avatarImg, description, secret,
    timeline: ["21:15 - 내용"], // 이 형식이어야 시각이 파싱됨
    fakeTimeline: ["21:15 - 거짓"], // 진범만. timeline과 같은 줄 순서
    alibiCards: [{ id, name, desc, img }] // 5장
  }],
  clues: [{ id, name, desc, img }],
  endings: {
    truth, // 엔딩의 사건 전말
    citizenWin: { title, badge, bannerImg, epilogues: { "<캐릭터 id>": "후일담" } },
    killerWin:  { title, badge, bannerImg, epilogues: { "<캐릭터 id>": "후일담" } }
  }
  // 선택: decisiveClues, killerDecisiveClues, 또는 진범 인물의 decisiveClues
  // 단서 id 문자열, 설명 문자열, 또는 { name|title, desc|text }
}
```

`isDefault: false`인 인물은 5명이 모일 때만 선택됩니다. `fakeTimeline`이 있는 진범만 공개 화면에서 줄마다 진실/거짓을 고릅니다. `decisiveClues`가 없으면 엔딩의 결정적 단서 자리는 진범의 진실·거짓 타임라인과 `endings.truth`로 채워집니다.

## 로컬 실행과 배포

스크립트가 ES 모듈이라 `file://`로 `index.html`을 열면 동작하지 않습니다. 저장소 루트에서 정적 서버를 띄웁니다.

```bash
python3 -m http.server 8080
```

브라우저에서 `http://localhost:8080/` 을 엽니다. 테스트 모드는 `http://localhost:8080/?test=1` 입니다. Firestore에 접속하므로 네트워크가 필요합니다. 별도 빌드나 패키지 설치는 없습니다.

배포는 GitHub Pages로, 소스는 `main` 브랜치 루트입니다. 워크플로 빌드나 `gh-pages` 브랜치는 없습니다. `main`에 반영되면 [게임 주소](https://bit.ly/4i6nEcs) 에서 같은 정적 파일을 제공합니다. 경로가 상대 경로이므로 저장소 이름 `Home` 아래에서도 그대로 열립니다.
